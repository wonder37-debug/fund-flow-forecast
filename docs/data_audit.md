# 数据审计

在本地对五张原始 CSV 执行全量预处理。机器可读结果为 `results/audit/data_audit.json` 和 `results/audit/coverage_by_day.csv`，分别包含全表审计统计和全人群日级覆盖人数。

## 表结构、键与覆盖

| CSV | 行 × 列 | 原始读取类型 | 日期或用户覆盖 |
| --- | ---: | --- | --- |
| `user_balance_table.csv` | 2,840,421 × 18 | 用户键、日期、余额和交易渠道为整数，4 列含空值的类别金额最初推断为浮点数 | 28,041 名用户。2013-07-01 至 2014-08-31 连续 427 天 |
| `user_profile_table.csv` | 28,041 × 4 | `user_id`、`sex`、`city` 为整数，`constellation` 为字符串 | 28,041 名用户，`sex` 有 2 种编码、`city` 有 7 种编码、`constellation` 有 12 种值 |
| `mfd_day_share_interest.csv` | 427 × 3 | `mfd_date` 为整数，2 个收益字段为浮点数 | 与全部 427 个交易日相交 |
| `mfd_bank_shibor.csv` | 294 × 9 | `mfd_date` 为整数，8 个利率字段为浮点数 | 2013-07-01 至 2014-08-29 有 294 天记录 |
| `comp_predict_table.csv` | 3 × 3 | 日期和两列金额为整数 | 2014-09-01 至 2014-09-03，三行均属目标月 |

五张表均无整行空白、全行重复或主键重复。`user_balance_table.csv` 的 `(user_id, report_date)` 唯一，日期和用户键无空值。交易表的 2,840,421 行都匹配唯一用户资料，资料表的每个用户都至少有一条交易记录。原始交易表只有四个 `category` 字段有空值，其余 14 列及另外四张表的列均无空值。交易金额、两列余额、四列类别金额及提交样例金额的已观测值均非负。审计 JSON 按列记录观测数、缺失数、零值数和负值数，非零金额仅按固定的绝对金额区间报告条数。

## 金额核账

以余额交易表为准逐行检查。各式的残差为左侧金额减去右侧金额合计。

| 业务等式 | 可核对行 | 残差非零 | 缺项行 |
| --- | ---: | ---: | ---: |
| `total_purchase_amt = direct_purchase_amt + share_amt` | 2,840,421 | 0 | 0 |
| `total_redeem_amt = consume_amt + transfer_amt` | 2,840,421 | 0 | 0 |
| `direct_purchase_amt = purchase_bal_amt + purchase_bank_amt` | 2,840,421 | 0 | 0 |
| `transfer_amt = tftobal_amt + tftocard_amt` | 2,840,421 | 0 | 0 |
| `consume_amt = category1 + category2 + category3 + category4` | 173,739 | 0 | 2,666,682 |

`category1` 至 `category4` 在 2,666,682 行（93.88%）同时为空，无部分缺失。这些行的 `consume_amt` 全为 0，类别完整的 173,739 行的 `consume_amt` 均为正。类别未填与无消费在该批数据完全对应。类别值在 L1 中保留空值，在 L2 和 L3 中按各字段已观测值求和。交易表还有 888,089 行的申购和赎回均为已观测的 0，与缺少用户日记录和字段缺失分开计数。某日已记录用户有目标字段缺失时，L3 对应模型目标为空，保留原名金额列的已观察小计。真实数据中两个日级目标的不完整天数均为 0。

逐项检查 16 列金额与余额。L3 全期合计和 L1 相应原始字段完全一致，三种静态分群每种单独按日合并也与 L3 的对应字段一致。全期总申购为 92,591,083,456 分，全期总赎回为 72,718,297,570 分。各金额字段的精确全期合计可由 JSON 中的 `amount_fields` 核对。若某列只有一个非零值，程序仍执行核账，并以 `totals_withheld` 标记其全期合计已隐去。

本批数据的完整记录上未发现等式偏差。对于等式不成立的输入，程序报告残差方向的计数、固定绝对金额区间的计数、受影响范围及涉及的零值成分。区间从 1 至 99 分起，逐级扩展至 1 亿分及以上。归因需要业务定义或交易事件记录。

## 用户记录分布与首次观察

每个用户的记录量为 1 至 427 天，中位数 16 天，均值 101.30 天，四分位区间 1 至 197 天。10,812 名用户仅有 1 条记录。全程单日观察用户数为 441 至 12,614，申购金额大于零的单日人数为 308 至 7,976，赎回金额大于零的单日人数为 30 至 1,312。

首日记录中有 441 名首次观察用户，后续共有 27,600 名首次观察用户，单日首次观察人数为 13 至 441。首次观察仅表示原始观测窗内的第一次出现，首日用户存在左截断，无法从记录推断开户日。末日仍观察到 12,614 名用户，观察窗结束前的最后出现日期同样不能确定销户。按月分布和记录条数分桶见 JSON，逐日首次及最后观察人数见 `coverage_by_day.csv`。

## 外部数据可用性与提交格式

收益表覆盖全部 427 个历史交易日期。SHIBOR 在历史交易日期观察到 294 天，133 天无记录，其中 116 个按星期计算的周末和 17 个星期一至星期五。另有 6 个周末日期在源表中有记录。连接依据源日期，保留未匹配的历史空值。

2014-09-01 至 2014-09-30 的预测区间，随附收益表和 SHIBOR 表均提供 0 天记录。同日实际值缺乏可用来源，训练和回测按截止日约束历史外部特征。CSV 中的日期覆盖仅证明该批文件存在历史记录，无法推出每条数据在当时的实际发布时间。

提交样例为无表头、逗号分隔的三列整数。列序为 `YYYYMMDD`、申购分、赎回分，日期升序。样例的 3 行用于校验解析，正式预测应覆盖 2014 年 9 月的 30 个自然日。[数据字典](data_dictionary.md)
