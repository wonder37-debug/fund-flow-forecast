# 阶段一评估协议

从项目根目录运行。程序默认从 `data/processed/daily.parquet` 读取 `report_date`、`purchase` 和 `redeem`，两个目标均为每日合计的整数分。日期需覆盖对应训练窗和验证窗。以 CSV 作为日表输入时，日期采用统一的 `YYYY-MM-DD` 或 `YYYYMMDD` 格式。按日期评分时，真实和预测都需提供唯一、有序且一一对应的日期。

```powershell
.venv/Scripts/python.exe -m experiments.baselines --run-id phase1-default
.venv/Scripts/python.exe -m pytest -q tests/test_evaluation.py
```

`--run-id` 可省略，由程序生成唯一 ID。重复 ID 会报错。`--daily`、`--sample` 和 `--results-dir` 可指定输入、样例和产物目录。6 个基线均为确定性方法，`--seed` 默认为 42，记录在运行清单中。

## 时间切分与选择

| 用途 | 训练截止日（含） | 默认预测区间（含首尾） | 默认预测天数 |
| --- | --- | --- | ---: |
| 选择 | 2014-03-31 | 2014-04-01 至 2014-04-30 | 30 |
| 选择 | 2014-04-30 | 2014-05-01 至 2014-05-31 | 31 |
| 选择 | 2014-05-31 | 2014-06-01 至 2014-06-30 | 30 |
| 选择 | 2014-06-30 | 2014-07-01 至 2014-07-31 | 31 |
| 最终离线评估 | 2014-07-31 | 2014-08-01 至 2014-08-31 | 31 |
| 生成提交 | 2014-08-31 | 2014-09-01 至 2014-09-30 | 30 |

每折在同一截止日拟合一次，直接预测后续多天。后续真实值只用于评分。根据 4–7 月四折的加权 MAPE 等权平均值选出一个基线，分数相同时按模型编号排序。模型选择结束后计算 8 月全部基线的离线指标。此前的 EDA 已查看 8 月，因此 8 月作为固定离线评估月份使用，不能视为盲测。生成 9 月提交时，用入选基线分别重新拟合申购和赎回数据。

默认从首个观测日开始扩展训练窗并评估完整自然月。`--horizon fixed30` 用于稳健性对照，将 4–8 月五折均设为月初起连续 30 天，省略 5 月、7 月和 8 月的第 31 天。9 月提交始终从 8 月 31 日截止的历史生成固定 30 天预测。`--training-window rolling --rolling-days 90` 对每个截止日使用含当天的最近 90 天历史，并对月度评估和 9 月重训执行同一规则。示例命令如下。

```powershell
.venv/Scripts/python.exe -m experiments.baselines --horizon fixed30 --training-window rolling --rolling-days 90 --run-id phase1-fixed30-rolling90
```

## 模型与可用信息

| 模型 | 候选历史 | 统计方式 |
| --- | --- | --- |
| B0 | 当前训练窗内全部日期 | 全体日均值 |
| B1 | 当前训练窗与最近 28 天的交集 | 全体日均值 |
| B2 | 当前训练窗内全部日期 | 同星期几的历史均值 |
| B3 | 当前训练窗与最近 28 天的交集 | 同星期几的历史均值 |
| B4 | 当前训练窗与最近 56 天的交集 | 同星期几的历史均值 |
| B5 | 当前训练窗与最近 84 天的交集 | 同星期几的历史均值 |

`fit(history)` 每次只接收 `report_date` 和待建模目标，`predict(future_calendar)` 只接收预测日期。分组用日期计算星期几，某个星期几在训练窗中缺席时使用该模型候选历史的总体均值。目标、交易人数、余额、收益率和 SHIBOR 等字段的未来值全部留在预测接口之外。申购和赎回分别拟合，用同一编号标识模型配置。

后续阶段可调用 `predict_targets(history, future_dates, model_factory, calendar_columns=...)`。工厂根据单个目标名构造模型。显式声明的日历字段来自 `build_calendar`，训练和预测均按日期对齐。预测返回与传入预测日历索引一致的非负、有限数值 `Series`。阶段一的工厂调用采用默认空日历字段列表。

基线仅使用均值。供后续阶段使用的 `causal_target_features` 接收按日排序的值序列，lag 取此前的行，rolling mean 先 `shift(1)`，满窗才定义。`fit_standardizer` 在传入的训练行上估计列均值与总体标准差，常量列使用 1 作为缩放系数。验证和预测行沿用拟合出的参数。测试用扰动数据覆盖了时间边界、未来目标和外部变量隔离、lag、rolling 及标准化。

## 指标

所有比率在 CSV 中使用小数。设单日真实值为 `a`、预测值为 `p`，绝对误差取 `abs(p - a)`，相对误差取 `abs(p - a) / a`。

| 指标 | 计算口径 |
| --- | --- |
| MAPE | 对 `a > 0` 的日期取相对误差平均值 |
| 加权 MAPE | `0.45 × 申购 MAPE + 0.55 × 赎回 MAPE`，用于本地比较 |
| MAE | 所有日期的绝对误差平均值，单位为分 |
| RMSE | 所有日期的平方误差均值再开方，单位为分 |
| WAPE | 所有日期的绝对误差之和除以真实值之和 |
| Bad Day | 在 `a > 0` 的日期中，相对误差严格大于 30% 的比例 |

真实值为 0 时，逐日相对误差留空，并从 MAPE 和 Bad Day 的分母中排除。真实值为 0 的日子仍参与 MAE、RMSE 和 WAPE，若整折真实值之和为 0，则 WAPE 留空。任一目标全折无正真实值时，该折加权 MAPE 无定义。选模遇到无定义的加权 MAPE 会报错。45/55 加权 MAPE 是本项目采用的离线诊断，线上竞赛评分以竞赛平台公布的公式为准。四折汇总采用等权均值，标准差采用样本标准差（`ddof=1`）。评分用未舍入的浮点预测。

## 产物

| 路径 | 内容 |
| --- | --- |
| `results/metrics/<run-id>/manifest.json` | 运行 ID、输入 SHA256、可取得时的 Git HEAD 与运行源码变更状态、运行源码 SHA256、环境版本、配置、特征名单、入选模型和耗时 |
| `results/metrics/<run-id>/fold_metrics.csv` | 全部 30 个模型和折组合的评分、训练窗和有效历史范围、预测范围、拟合和推理耗时 |
| `results/metrics/<run-id>/daily_predictions.csv` | 逐日真实值、预测值与两目标相对误差，含截止日和预测步长 |
| `results/metrics/<run-id>/selection_summary.csv` | 4–7 月按模型汇总的各指标均值和标准差，按加权 MAPE 排序 |
| `results/submissions/<run-id>.csv` | 2014 年 9 月 30 天的竞赛提交文件 |

写出提交文件前，程序会读取 `Purchase Redemption Data/comp_predict_table.csv`，检查样例的无表头三列格式和日期顺序。输出依次为 `YYYYMMDD` 日期、申购整数分、赎回整数分，共 30 行。小数分按四舍五入转为整数，负数、非有限值、缺失日期、重复日期与日期顺序错误均会报错。
